# PRD: AI 일본어 회화 연습장 (B2C)

작성일: 2026-11-03 · 상태: 초안

이 문서는 [raw-notes.md](raw-notes.md)(기획자 원문), [problem.md](problem.md), [decisions.md](../decisions.md), [research.md](research.md)(조사 자료)를 근거로 쓴다. 8장의 '유지' 기능과 5장의 기능 설명은 현재 구현(README, [erd-api-spec.md](../contracts/erd-api-spec.md), 코드)을 근거로 쓴다. 근거가 없는 내용은 15장 "열린 질문"에 둔다. 이전 B2B2C 버전은 태그 `v1.0-b2b2c`에 있다.

## 1. 한 줄 정의

연습 상대 없이도 원할 때 AI와 일본어로 대화하며 회화 실력을 키우는 서비스.

근거: raw-notes.md 2026-11-02, 2026-11-03

## 2. 문제

일본어 회화를 연습하고 싶어도 연습 상대를 구할 수 없다.

- 한국에 살면서 일본인 친구를 만들기 어렵다.
- 회화 모임은 매일 할 수 없고, 매주 오프라인으로 모여야 하며, 장소가 멀면 가기 힘들고 시간이 많이 든다.
- 일본어 영상은 직접 대화하는 게 아니라 따라 하는 것이고, 영상 속 흐름에 맞출 수밖에 없다.
- 아직 서툰 사람은 실제 사람과 대화하는 게 부끄럽다.
- 일본인과 대화하면 조금 틀리게 말해도 원어민은 알아듣기 때문에, 하나하나 교정해 주거나 지적해 주지 않는다.

모두 기획자가 직접 겪은 일이다.

근거: problem.md

## 3. 왜 지금인가

기획자가 일본어 회화 실력이 녹스는 것을 느끼면서, 이런 연습 수단이 지금 필요하다고 느꼈다. 2장의 문제는 모두 기획자가 직접 겪은 일이다.

근거: raw-notes.md 2026-11-02, 2026-11-03, problem.md

## 4. 타깃

일본어를 어느 정도 구사하는 학습자. 사용 목적(취미, 일본 생활 준비 등)은 가리지 않는다.

| | 누가 | 언제 |
|---|---|---|
| A | 아직 조금 서툴러서 연습하고 싶은 사람 | 실력을 기르고 싶을 때 |
| B | 말하는 건 어렵지 않지만 실력이 녹슬지 않게 관리하고 싶은 사람 | 일본어를 까먹지 않게 연습하고 싶을 때 |

초급자를 주 타깃으로 설계하지는 않지만, 일반 회화의 페르소나 설정에서 난이도와 연습 상황을 직접 정할 수 있어 초급자도 쓸 수 있다.

근거: problem.md, decisions.md 2026-11-02 "B2C 기획 범위"

## 5. 솔루션

AI와 일본어로 직접 대화한다. 연습으로 쓸지, 취미로 쓸지, 학습으로 쓸지는 사용자가 정한다.

**지향점: 정확하게 말하기보다 자연스럽게 말하기.** 그래서 대화 중에는 교정하지 않고 대화 흐름을 지키며, 교정은 대화가 끝난 뒤 피드백으로 모아서 준다. 선행 연구는 결과가 엇갈리고(즉시 교정이 같거나 낫다는 연구가 더 많다), 대화 후 피드백이 학습에 더 효과적이라는 근거는 없다. 한국인 성인의 AI 일본어 음성 대화를 직접 비교한 연구도 없다. 그래서 학습 효과가 아니라 대화 흐름을 기준으로 고른 설계다([research.md](research.md) 6절, decisions.md 2026-11-03 추가).

| 2장의 문제 | 해결 방식 |
|---|---|
| 연습 상대가 없다 | 역할과 성격을 정한 AI 페르소나가 대화 상대가 된다. 대화 상황도 사용자가 직접 정한다 |
| 모임은 매일 못 하고, 멀고, 시간이 든다 | 웹에서 원하는 시간에 원하는 만큼 쓰고, 중간에 끝낼 수 있다 |
| 영상은 따라 하기라 대화가 아니다 | 사용자의 말을 알아듣고(STT) 대답하고(LLM) 소리로 들려준다(TTS). AI가 먼저 말을 건다. 면접은 답변에 맞춰 꼬리 질문을 한다 |
| 서툰 사람은 사람 앞이 부끄럽다 | 상대가 AI라 부끄러움과 어려움이 적다. 녹음을 취소하고 다시 말할 수 있다 |
| 수준이 사람마다 다르다 | 초급·중급·고급 난이도와 자막 설정 |
| (B) 녹슬지 않게 관리하고 싶다 | 학습 기록에서 지난 대화와 피드백을 다시 본다 |
| 원어민은 틀려도 알아들어서 교정해 주지 않는다 | AI가 사용자의 말을 모두 기록하고, 어디가 틀렸는지, 어디가 부자연스러웠는지, 어떻게 더 자연스럽게 말할 수 있는지를 피드백으로 남긴다 |

근거: raw-notes.md "해결책 메모", 2026-11-03 (Claude가 기존 기능을 2장 문제에 연결해 제안하고 기획자가 승인). 기능 설명은 README, erd-api-spec.md

## 6. 핵심 시나리오

기존의 두 모드를 그대로 둔다.

- **일반 회화**: 상황과 대화 상대(페르소나)를 정하고 AI와 일본어로 대화한다.
- **면접 회화**: AI 면접관과 일본어 면접을 연습한다.

두 모드가 함께 있는 이유는 아직 명확하지 않다(15장 열린 질문 1).

근거: raw-notes.md 2026-11-02, decisions.md 2026-11-02 "B2C 기획 범위"

## 7. 사용자 흐름

```
가입 → 튜토리얼 → 대시보드 → 회화 연습 → 피드백 확인
```

대시보드와 피드백 화면은 현재 구현 상태를 그대로 둔다. 튜토리얼은 화면 설명 페이지이며 가장 마지막에 만든다.

## 8. 기능 요구사항

구분: **유지**는 B2B2C 버전에 구현되어 있고 그대로 두는 기능, **변경·추가·개선·제거**는 이번에 바꾸는 기능이다. 유지 기능의 세부 내용은 현재 구현 문서(README, [erd-api-spec.md](../contracts/erd-api-spec.md))를 근거로 적었다.

### 8.1 계정

| 구분 | 기능 | 내용 |
|---|---|---|
| 변경 | 회원가입 | 일반 사용자만 가입한다. 기관 선택과 가입 승인 절차가 없고, 가입 직후 바로 쓸 수 있다 |
| 유지 | 로그인·로그아웃 | 이메일·비밀번호 로그인. JWT로 인증하고, 사용자 정보는 토큰에서 얻는다. 로그아웃은 사이드바 메뉴에 있다(`frontend/src/components/layout/Sidebar.jsx`). 서버 쪽 로그아웃·토큰 폐기 정책은 미확정이다(backend-rules.md "현재 미확정 사항") |
| 유지 | 설정 | 기본 난이도와 기본 자막 모드, 비밀번호 변경. 화면은 있지만 실제 API 연동은 남은 이슈 #3이다(15장 열린 질문 4) |
| 제거 | Admin, Manager | 기관·Manager 관리, 학습자 승인·거절·활성화·비활성화, 기관·서비스 Dashboard를 없앤다 |
| 제거 | 기관(Organization) | 기관 소속을 두지 않는다 |

### 8.2 안내

| 구분 | 기능 | 내용 |
|---|---|---|
| 추가 | 튜토리얼 | 화면을 설명하는 안내 페이지 하나. 가입 직후 한 번만 뜨고, 사이드바 구석 버튼으로 다시 볼 수 있다. 시뮬레이션은 아니다. 개발 순서상 가장 마지막에 만든다 |

### 8.3 일반 회화

| 구분 | 기능 | 내용 |
|---|---|---|
| 유지 | 회화 설정 | 상황, 상황 설명, 대화 상대의 역할과 성격, 난이도(초급·중급·고급), 자막(끔·일본어·일본어+한국어)을 정한다 |
| 유지 | AI 선발화 | 대화를 시작하면 AI가 먼저 말을 건다 |
| 유지 | 음성 대화 | 사용자가 녹음해 말하면 받아쓰기(STT)로 글로 바꾸고, AI가 일본어로 대답하고(LLM), 음성으로 들려준다(TTS) |
| 유지 | 녹음 취소 | 녹음 중에 취소하고 다시 말할 수 있다. 대화를 끝낼 때 진행 중인 녹음은 취소된다(커밋 20819d0, 180cd35) |
| 유지 | 종료·중단 | 정상 종료하면 피드백을 만든다. 중간에 그만둘 수 있다 |
| 유지 | 회화 피드백 | 숫자 점수 없이 요약, 자연스러움·문법·어휘 코멘트, 잘한 점, 다음 학습 팁. 사용자 발화별로 원래 표현, 더 자연스러운 표현, 읽기, 한국어 번역, 설명을 보여준다 |
| 개선 | 받아쓰기(음성 인식) | 큰 목소리는 비교적 잘 받아 적지만, 사람의 실제 말은 그렇지 않다. 말하다 취소하고 다른 말을 하거나, 작게 말하거나, 문법적으로는 틀려도 맥락상 가능한 말을 한다. 이런 말을 **고치지 않고 들은 그대로** 받아 적는다 |
| 개선 | 대화 상대 AI | 받아 적은 말의 맥락, 흐름, 분위기까지 이해하고 대답한다. 사람과 나누는 대화와 차이가 없게 하는 것이 목표다 |
| 개선 | 회화 피드백 | 세 가지를 구분해 준다. ① 문법적으로 틀린 말은 틀렸다고 지적한다. ② 문법적으로 틀려도 자연스러운 말은 그대로 써도 괜찮다고 알려 준다. ③ 문법적으로 맞지만 더 자연스러운 표현이 있으면 제안한다 |

세 개선은 5장 지향점(정확하게 말하기보다 자연스럽게 말하기)을 따른다.

## 9. 사용자가 얻는 결과

서비스를 쓰고 나서 사용자에게 남는 것:

- **A**: 회화 실력을 키운다.
- **B**: 실력이 녹슬지 않게 유지한다.
- 사람 앞에서 부끄럽지 않게 연습한다.
- 시간과 장소에 묶이지 않고 연습한다.

## 10. 범위

**포함**: 8장의 유지·변경·제거·추가·개선 항목.

**제외**
- 튜토리얼 외의 새 기능. 새 기능을 넣게 되면 그때 기획을 따로 쓴다.
- 학습 동기부여 요소. 보통의 언어 학습 플랫폼처럼 "무엇을 하면 실력이 얼마나 는다"거나 매일 참여하게 만드는 장치는 두지 않고, 사용자의 의지에 맡긴다.

**진행 순서**: 기존 기능 수정 → 남은 이슈 정리 → TypeScript를 공부하며 조금씩 전환 → 추가 기능 제작. 튜토리얼은 이번 범위에 포함하되 가장 마지막에 만든다.

**목표 범위**: 출시하지 않는다. 기획부터 개발, 배포까지 직접 경험하고, 내가 쓰고 싶을 때 접속해 쓰는 수준이다.

근거: decisions.md 2026-11-02 "B2C 기획 범위"

## 11. 성공 지표

품질과 사용 두 측면을 모두 계획한다. 아래 지표와 측정 방법은 Claude가 후보로 제안하고 기획자가 "품질, 사용 측면에서 다 계획"하기로 승인한 것이다. 측정 방법의 세부 정의와 목표 수치는 15장 열린 질문 3.

| 측면 | 지표 | 측정 방법 | 확인 계획 |
|---|---|---|---|
| 품질 | 받아쓰기 정확도 | 문자 오류율(CER). 일본어는 글자 단위로 잰다 | 받아쓰기 개선 전후를 비교해 포트폴리오에 반영한다 |
| 품질 | 응답 대기 시간 | 사용자가 말을 끝낸 뒤 AI 음성이 나올 때까지 | 최대한 줄이고 포트폴리오에 반영한다 |
| 품질 | 피드백 생성 성공률 | 생성 요청 대비 완료(`COMPLETED`) 비율 | 같음 |
| 품질 | 세션당 API 비용 | 받아쓰기·대답·음성 생성 비용 합계 | 같음 |
| 사용 | 회화 완료율 | 시작한 대화 중 정상 종료한 비율 | 가능하면 테스터를 모집해 확인한다. 안 되면 "계획했지만 출시하지 않아 확인하지 못했다"로 남긴다 |
| 사용 | 주간 재방문 | 한 주에 다시 접속해 대화한 사용자 비율 | 같음 |
| 사용 | 세션당 대화 턴 수 | 한 대화에서 주고받은 횟수 | 같음 |
